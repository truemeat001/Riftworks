# P05 角色美术、帧动画与头像冻结记录

状态：用户批准的 Concept A（手绘航海微缩剧场）对应的实际运行资源，不是把概念图贴在战斗界面。重新制作角色与敌人，完全不沿用 NGame/P04 的角色像素图。仅复用前轮验证过的逐帧图集、透明 AABB、锚点、边缘保护、逻辑与演出分离技术。目标是贴近 A 的造型、镜头、哑光材质、柔和轮廓和海盐蓝/暖象牙/珊瑚色气氛；未声称与参考图逐像素相同。Boss 在 A 未单独呈现，采用同世界观原创补充。

40 个原创 ImageGen 动作源姿势。每个角色保留 P04 逻辑 ID，动作合约：

- 友方 idle 2（4 FPS，站立/回位），attack 6（18 FPS，源四个姿势，明确停顿和回位）；固定驻位角色没有虚构走路、受击、阵亡动作。
- 敌方 idle 1（静态尺寸参考），run 4（8 FPS，全部是独立源动作），hurt 2（12 FPS），death 4（9 FPS，受击、倒下、倒下停顿、躺倒）。
- 每个 clip 含原向右和 _left 镜像条目，合计 136 个图集表项，允许明确的节奏停顿。镜像在统一脚锚线，不通过旋转人体表现上下方向；当前为左右朝向近似，真正四/八方向手绘仍待扩展。
- 素材可供表现层事件使用，不新增逻辑行为。模型 20Hz 权威 tick 保持不变，受击和死亡帧不会执行伤害计算，暂停/倍速与事件时间一致由 UI 负责。

## 资产接入

- assets/characters/atlas.png：2048×2006 RGBA，4,410,604 字节
- assets/characters/manifest.json：保留 characters[id][state]、states[state].fps/loop、frame.rect 与 frame.offset 字段；额外包含 portrait、源图和锚点追溯信息。
- assets/characters/portraits/pulse.png、frost.png、burst.png：256×256 带透明通道的独立胸像头像，源自新角色造型，适用于待命卡与详情框。头像本为胸像，左右/底部有构图裁边。
- assets/characters/concept-lineup.png：实际源动画 idle 资产排队，非原始概念图。
- docs/character-motion-preview.gif：按角色运行尺寸生成的 34 帧循环预览；docs/character-idle-preview.png 和 character-attack-preview.png 为静态关键帧。它们是实际美术资产动作证据，不是游戏录屏。
- docs/art-sources-p05/：独立原始 ImageGen 图及清洁编辑版本；.gdignore 防止 Godot 扫描导入。源图只用于追溯/打包，不作为运行时贴图。

建议表现层使用 LINEAR 采样，而非旧像素 NEAREST；2px 透明采样保护。固定统一 400×400 工作画布，锚点 (200,310)。每种角色在同一源表中的比例固定，不逐帧拉伸。友方直接根据原图人工标定每帧鞋底接触，避免锤击/长围巾改变矩形中心造成抖动；鳐鱼采用独立身体下方参考点而非翼尖；其余怪物采用不透明脚底 10% 区域中点。透明裁切后以每帧 offset 还原锚点，绘制的阴影由 UI 分层，不是贴图中的底座。正常友方展现目标约 70–88px 高；潮蟹小而紧凑、鳐鱼宽而矮，不能简单把每个敌人的高度统一拉满格子；Boss 建议明显更宽更高。不能用图片大小代替碰撞/点击坐标。

## 原创生成过程

内置 ImageGen（没有额外 API Key 或付费调用）以经用户批准的 Riftworks-P05-concept-A.png 作为视觉参考。

1. crew-original-with-haze.png — 提示：严格按 A 三个角色身份、略 60° 斜俯 3/4 朝右视角、同一角色四个姿势（站立、预备、释放、回位），3×4 隔离全身透明格；奶白、海蓝、暖珊瑚，手绘哑光水粉，禁止像素风、深黑铠甲、地板或 UI。初次输出背景残余半透明雾。
2. crew-poses.png — 内置 ImageGen 清洁编辑；仅要求去除全部灰雾、地板、影子和纸填充，保留 12 个原角色姿势及实际动作。经 alpha 检查，大量背景像素确实 0 或 1，最终使用这个版本，保留第一版追溯。
3. enemy-walk.png — 参考 A 中橙蟹、蓝鳐、珊瑚怪造型，为冠状 Boss 设计补充同风格；4×4 四移动姿势，足或鳍支撑交替，透明背景、不烧录路径与地板。
4. enemy-damage.png — 以新 enemy-walk 为身份参考，每行同一怪物三态（受击、塌落、躺倒），保持角色色与材料，动作独立，不是旋转截图或整图位移。
5. crew-portraits.png — 以新 crew-poses 为原角色参考，3 个胸像，清晰同角色脸、服饰、柔和材质；使用卡片局部裁剪避免相邻胸像，保留实际细节与透明 alpha。头像在 #F5EBD6 奶白背景合成检视，无明显矩形杂底。

打包脚本通过 alpha>=128 的主体位置确定源单元格边界与 3px 安全外边距，仅据此裁剪，保留裁切内部的源透明通道与反走样细节；源工作图与 atlas 都可重新构建。固定逐角色源比例 LANCZOS 减小至实际游戏素材，使用 2px 边缘/四角外扩防双线性采样串色。所有帧和头像软件处理为工程必要的切片和缩放，不通过算法伪造新的动作姿势。原始源表行列间距不完全等宽，已按实测透明投影间隙记录。角色图集无任何 NGame 或 P04 像素源图。

## 复验与冻结

在 RiftworksP05 项目目录执行：

    python assets/characters/generate_character_atlas.py
    python assets/characters/verify_character_atlas.py
