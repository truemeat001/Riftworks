# Riftworks 交互设计与验收规范 v1.0
状态：项目通用门禁；P05 具体实现以已确认玩法和实际验收为准。原则：玩家能发现、能理解、能操作、能恢复；不为了视觉牺牲反馈。默认移动端触控设计审查，但当前版本仅声明 PC/Web 键鼠，移动端未真机验收。

## 1. 每次输入模板
- 任务：设计新交互／审查现有交互；对象：地图/布阵/开箱/合成/出售/弹窗等。
- 玩家目标、入口与场景、平台和输入方式、已确认规则、参考（策划文档、线框、实机截图/录屏、设计规范）。
- 每条未确认规则标「待确认」及影响，不自行更改玩法。先定义成功、失败、返回状态和验收证据，再做美术。

## 2. 主流程（强制）
入口（首次不看说明能发现）→ 可用条件或原因 → 输入（触发热区/开始条件/控制优先级）→ 按下、预览/处理中 → 成功或失败的可读反馈 → 继续任务或返回原层。
- 面板关闭回到入口场景；保留地图位置、滚动和有效选择，丢失/消耗对象则显式清除；取消不消耗，不能悄悄改变选择。
- 状态必须由游戏逻辑产生，展示的花费、收益、禁用原因与真实规则一致。界面动画仅表现；一次有效动作只提交一次，重复点击不可多扣、多发或切错对象。
- 危险操作按后果确认：出售、不可逆重开/放弃进度须清楚对象、数量/后果、确认和取消；结果未确认时禁止造成重复请求。如果后续增加联网，提交用唯一动作ID，重复请求幂等；超时/重连查询权威结果再决定是否重试，不把超时当失败或自动补扣。当前 P05 本地确定性运行，不假造联网状态。
- 失败反馈写原因和建议（例如余额不足、路径禁止布阵、格已占用、阶位不符、容量已满）。按规则返回可继续操作状态，保持原有资产。

## 3. 输入规范
| 输入 | 触发/开始 | 过程反馈 | 松开/完成 | 取消/优先级 |
|---|---|---|---|---|
| 鼠标左键/触屏点按 | 可见有效按钮或可选对象；按下有状态 | 选中轮廓、合法候选、错误原因 | 释放同一控件才执行；点地图合法格部署 | 离开控件、失焦、Esc/可见取消；UI先于地图 |
| 右键/键盘 | 当前键鼠支持右键收回，Esc退出暂态，Space暂停 | 角色提示与按钮同步 | 按对应状态生效 | 不截获有文字输入/焦点控件的通用快捷键；移动端必须有可见等价收回 |
| 长按（未来） | 角色/物件触发区，建议阈值300–500ms待实测 | 信息浮层或按住进度，不能消耗 | 放开只完成指定非危险动作 | 移动超过阈值/第二指/系统取消；点按与长按不同时执行 |
| 拖拽（未来） | 预备区/场上已选对象，建议移动超过8–12逻辑像素进入拖拽，阈值待测 | 抬起预览偏离手指，合法/非法落点及范围 | 合法释放才提交，失败回原位 | 松手越界、Esc、系统取消、第二指均无损；对象拖动优先于地图平移，空地才平移 |
| 双指（未来） | 两指有效触点，当前固定镜头不支持 | 缩放/平移反馈稳定 | 保留合法视角范围 | 第二指取消尚未提交拖拽；不触发地图部署；不可误扣 |
触屏不是简单把鼠标像素当 pt/dp：以实际设备安全区、缩放和手指热区检查，频繁控件目标至少44×44pt（iOS 指南）、Android依平台规范及真机；按钮间距、可见按压反馈、拇指可达性、手指遮挡和系统边缘返回分别验收。不将必须收回/取消动作藏在右键/长按。滑动手势避免系统左右返回、底部 home；不无理由排除系统手势。

## 4. P05 本轮交互审查：开箱、布阵、合成、出售、开战
已确认规则：[P04 玩法](gameplay-p04.md)，[美术锁定](p05-concept-lock.md)。15生命/24开局金币，6币统一随机；起始不足2角色随机角色，否则按真实池；最多9拥有/5部署；基础售4、高阶8/16；同类同阶合成，遗物独立等级；战斗时禁止改变构筑。
### 主流程
1. 准备：顶部状态，探索入口与当前真实赔率、费用同屏；无队伍开战禁用并给理由。
2. 点击探索→明显按下/扣6→奖励到账并展示开箱动画→可免费跳过→同一真实对象进入待命或遗物界面。
3. 点击待命角色→合法可放置格、当前选中与能力→点击合法格→部署成功，非法格保持角色选中、资产不变并提示；可取消选择、收回再部署。
4. 选中同类同阶→合成→第二名合法目标→显示新阶位及变化；误选不消耗。出售时第一次只待确认，展示对象/数量/返还，确认后才变更，取消保持对象和地图；若选择改变取消旧确认。
5. 开战→阶段变化和敌人预告、可暂停/倍速→波结束、结算奖励→回准备；终局显示结果和重开。活跃Run重开/新局的确认行为待核验，若当前单击立即重置，应列阻断修复。
### 状态表
| 当前状态 | 触发条件 | 玩家可见反馈 | 可用操作 | 下一状态 |
|---|---|---|---|---|
| 准备/可抽 | 余额≥6、有合法池 | 按钮6币/概率 | 探索、选中、部署 | 揭晓或准备 |
| 准备/不可抽 | 余额不足/池满 | 明确原因 | 出售、开战(合法时) | 准备 |
| 揭晓 | 有唯一已到账奖励 | 宝箱打开/角色或遗物、余额 | 免费跳过、等待 | 已揭晓 |
| 已揭晓 | 动画结束或跳过 | 真实对象/仓位/等级 | 再探索或选择 | 准备 |
| 角色选中 | 点击待命/场上 | 选中、可部署点、统计 | 部署、合成、出售、清除 | 已部署/合成/确认/准备 |
| 非法落点 | 路线/占用/满编 | 原因与合法候选，角色不丢 | 重选点、Esc取消 | 角色选中 |
| 合成待选 | 同类同阶存在 | 目标标识、取消 | 同类同阶另一名、Esc | 已升阶或保持 |
| 出售待确认 | 选择有效角色/遗物并点出售 | 对象、返还、取消 | 确认同一身份/阶位、取消 | 结算/准备 |
| 战斗 | 至少一名合法部署后开始 | 敌人、进度、真实战况 | 暂停、倍速、查看 | 暂停/波结束/终局 |
| 终局 | 胜利/失败条件 | 结果与下一步 | 重试、新Run | 准备 |
### 可复现真机用例（不是通过声明）
- UXR01：新Run，没看说明→找到探索，查看消耗/概率→单击一次；24→18，正确奖到账一次；立即再点仅跳过，18不变化；再明确点才扣至12。
- UXR02：仓位选中→点击路径/占用/边界→提示对应原因，币、角色身份、位置不变；随后点合法格，可成功部署。
- UXR03：已部署角色→收回/取消→保留角色，数量和金币不变；点其他合法格重新部署；输入UI不穿透地图。
- UXR04：同类同阶两人→合成待选→点不同类/同一对象失败，Esc无消耗；合法不同ID成功升阶，数量减1，真实数值更新。
- UXR05：角色A→出售待确认→改选B/Esc/部署/开战或其他动作→无扣/返还；重开确认只对当前身份和阶位有效；两次确认同一A正确返还4/8/16。遗物同样检查。
- UXR06：无部署→Start禁用并说明；部署后→Start，抽取/合成/出售禁用，暂停/继续与倍速正常；结束波后恢复准备、状态奖励仅一次。
- UXR07：活跃局→Retry/New run→应提示重开将丢进度并可取消，取消保留原局；终局重开可直接进行（待核实实现）。
- UXR08：实际1280×800与960×600、窗口缩放/全屏，逐个操作入口无裁剪，点击坐标不偏移；四角/末格映射正确；九仓位八遗物均可查看。
- UXR09：若目标包括移动端，真实iOS和Android两设备依次检查拇指、热区、系统边缘、手指遮挡、触屏取消、点按与拖拽竞争；未支持/未测标明，不以模拟通过冒充真机。
### 审查记录格式
P0/P1/P2｜复现初始条件及步骤｜实际表现｜玩家影响｜已确认规则引用｜具体改法｜复验证据。P0是误扣/误删/回退损失、入口无法完成、卡死；P1是可完成但难发现/结果不明；P2可选体验偏好。不得用平均分掩盖阻断项。入口可发现性优先用未阅读说明的新玩家观察；自动测试不是新玩家证据。

## 5. 参考方法
- [Celia Hodent 游戏 UX 实践](https://celiahodent.com/ux-practices-epic-games/)：关注玩家心理模型、注意力和早期原型试玩，保留设计挑战；区分玩法难与操作不清。
- [Apple HIG Game Controls](https://developer.apple.com/design/human-interface-guidelines/game-controls)：直接操作对象、拇指范围、安全区、可见按压状态，以及平台默认输入；按实际设备验收。
- [Android 手势导航兼容指南](https://developer.android.com/develop/ui/views/touch-and-input/gestures/gesturenav)：系统边缘手势优先、合理处理冲突、有限排除；底部系统手势不能简单禁用。
- [Unity 游戏 UI/UX](https://unity.com/blog/video-game-ui-ux-basics)：拆分任务、反馈、界面层次、原型与可访问性验证。
