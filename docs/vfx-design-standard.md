# Riftworks 特效设计、制作与审查规范 v1.0
项目：手绘航海微缩剧场；依据 [DESIGN.md](../DESIGN.md)、[交互规范](interaction-design.md)、[序列帧规范](sequence-animation-standard.md)、[玩法规则](gameplay-p04.md)。信息先于装饰；不把概念图中的技能或数值当已实现规则。

## 1. 每次输入
任务（设计/制作/审查）、对象、玩家第一眼应理解的信息（范围、方向、命中点、状态或操作结果），触发事件与停止条件，世界/UI层、锚点/排序/遮罩、镜头尺寸，参考图/录屏各自用途、目标设备/并发与预算。未确认的判定、触发时序、设备和性能目标标「待确认」，不得凭视觉扩大或缩小实际判定。

## 2. 通用视觉语言与等级
| 等级 | 焦点与形状 | 颜色和层级 |
|---|---|---|
| 高频普攻/受击 | 短有方向感的弧、目标处小冲击；来源和命中不模糊 | 低面积、短寿命、保留敌轮廓/血条 |
| 控制/持续状态 | 目标锚定的独特轮廓、状态持续期间稳定 | 冰雾青蓝/结晶环+独特形状，不能只靠颜色 |
| 关键联动/构筑 | 导电：折线连接；碎冰：断裂放射碎片；并标明真实状态 | 突出峰值但不淹没普攻，标识/数字不重叠 |
| 可反应的危险预警 | 清楚边界和方向，按权威判定与生效事件持续 | 保留关键红/珊瑚危险，轮廓对比≥3:1目标；不伪造可躲避窗口 |
| 重大结果/结算 | 独特轮廓、收束到对应对象 | 宝箱、升阶、关键战果最强瞬时反馈，不长期照亮全屏 |
使用海盐蓝、暖沙、象牙、珊瑚、少量晶紫；手绘哑光和清晰图形，不用高饱和荧光覆盖场景。高频动作采用较小低亮度，预警/重大结果有最高信息优先级。环境装饰无干扰，色弱也可按形状、位置、节奏区别。

## 3. 时序生产模板
| 阶段 | 事件/时间点 | 可见变化 | 结束/取消 |
|---|---|---|---|
| 预警（如有） | 权威准备事件 | 判定边界、方向和将发生事件，不提前造成伤害 | 权威触发/取消；取消移除轮廓 |
| 触发 | 权威动作/命中 | 源与目标清晰，峰值开始 | 只消费一次对应事件，不因循环重触发 |
| 峰值 | 已确认命中或奖励 | 核心焦点对比最高，短瞬时反馈 | 进入持续/收尾 |
| 持续（如有） | 状态起止/剩余时间 | 绑定对象稳定轮廓与状态量 | 状态到期、死亡、取消、换关 |
| 收尾 | 演出结束 | 辅助烟尘/碎片消散、回静态或隐藏 | 保证资源回收无残留和逻辑副作用 |
没有实际前摇的 P05 即时攻击不画虚假警告。UI操作反馈按真实结果：开箱扣费与到账立即由Run提交，后续动画只演出；跳过不会再次抽取。

## 4. P05 例：潮雾、铜鸣导电、礁锤碎冰（下一轮优化设计，不冒充已实现）
已确认 Run.gd 冻结规则：Mist Weaver 命中施加 slow 时间=0.8s+freeze等级×0.6+0.25×(rank−1)；普通减速倍率 max(0.2,0.55−0.15×freeze等级)，Boss减速折减；铜鸣命中已减速目标的伤害×1.20；礁锤对已减速主目标时，溅射范围在基础 1.0+0.4×blast等级+0.2×(rank−1) 格之外+0.35格，次要目标溅射再×1.10。当前碰撞/伤害是即时，不凭动画判断命中。
| 阶段 | 触发 | 画面 | 结束 |
|---|---|---|---|
| 潮雾命中（0–100ms建议） | 实际命中/slow状态赋值 | 窄蓝白霜环、目标脚底结晶，短命中点 | 自然消退到持续态 |
| 潮雾持续 | slow>0 | 脚底蓝青晶形环与简明状态图标；随目标走 | slow<=0/敌死 |
| 导电（0–160ms建议） | 已减速敌人被铜鸣命中，synergy=conductive | 武器/目标短折线、电光只在真实命中点，短“导电”标记 | 无残留；连锁额外命中按实际目标独立 |
| 碎冰（0–180ms建议） | 已减速主目标被礁锤命中，synergy=shatter | 在命中点向外破碎的冰片；若显示范围边界，必须用实际本次半径和世界坐标，不画推广伤害 | 几何提示立即对应实际判定，不在收尾虚构持续伤害 |
| 辅助层（180–300ms建议） | 事件峰值后 | 少量碎片/淡水雾，低透明 | 及时回收；换关、重开、暂停遵循状态 |
资源：方向弧线/状态环用属性动画或Godot CanvasItem矢量，冰片裂纹需画形状变化时用透明序列帧，离散碎片可粒子；附同一源帧和图集元数据。世界挂点源武器/目标脚锚，视觉偏移与位置关联但不改变 hitbox；排序地面提示→单位/命中→血条和关键文字→HUD，遮罩在战场。事件唯一可追踪（动作ID/目标ID/tick），每动作与每命中语义分开；表现层订阅，不回写伤害、随机、经济；同动作次要命中不得重复触发全局奖励/升阶。

## 5. UI奖励反馈例（已确认规则+设计目标）
探索付6后收到唯一奖励，展示 P05 的 850ms 开合/弹出/落仓；未确认时不能误显示成第二个奖励。礼物轮廓与目标插槽对应；角色用真实帧，遗物用其实际图标（现版通用菱形待替换）；归仓时计数与新对象已真实存在，动画结束保留已到账状态。售卖待确认不能展示已返还；取消不闪奖励，真实确认后再显示币数变化。

## 6. 资源/性能规范
- 属性动画优先用于渐隐、位移、缩放、状态环；序列帧用于轮廓不连续的手绘形变；粒子只承担离散装饰。已有材质/栈/图集复用，避免每帧创建新材质和节点。
- 每项记录唯一事件ID、挂点、空间、遮罩、渲染顺序、开始/停止/池回收、峰值粒子数、最大同时实例、渲染尺寸和期限。低画质先减少烟尘、火花、拖尾数量/寿命/半透明覆盖，再降装饰采样；不删判定轮廓、命中位置或状态时序。
- 当前目标 PC/Web 1280×800、960×600；手机和GPU性能预算待确认。建议先以60fps目标(16.7ms总frame time)研究，测 CPU/GPU/Draw Calls、透明过绘、峰值帧时p95/p99及内存，记录机型/浏览器/分辨率/场景/速度和效果计数，不从图集面积或规则Tick推断GPU。
- 峰值场景：5部署、密集敌波+Boss、最高攻速/链击/碎冰和2x、升阶/开箱/跨关；同seed重复、30/60/120渲染节奏/长帧测试；表现降级不改变权威事件或胜负。
## 7. 验收/审稿（实际结果）
| 场景/触发 | 预期可观察 | P05实际/状态 |
|---|---|---|
| 开箱、免费跳过 | 真实到账一次，跳过无扣费，角色/遗物对应 | 原生角色开箱与余额、skip已通过；遗物已到账但弹出通用菱形，改实际图标 |
| 普攻/受击/死亡 | 源方向、命中点、受击帧、死亡回收 | 原生观察真实攻击与多种敌人，代码有事件/死亡帧；密集时短直线较单薄，完整三轮/高并发逐帧证据待验证 |
| 潮雾/导电/碎冰 | 真实状态、环和实际命中 | 现有细射线/小圆环/文字和 slow 脚环；下一轮用折线与结晶形状增强。禁止为视效改变判定 |
| 关卡增幅/联动 | 来自真实位置与距离，风格一致 | 第三关原生可见增幅与链接；暗紫方形AMP块偏工程图，改实体晶石台、仍对应相同格/距离 |
| 密集战斗 | 敌人轮廓、路径、血条、HUD仍可读 | 原生观察有同向敌人重叠；血条已有最后绘制，攻击线和文字不应再盖住它们。完善排序和轻量相位错位 |
| 暂停/恢复/跨关/重开 | 暂停不推进，切关无残留诺言 | 原生暂停/恢复和切关已测；独立129项UI逻辑合格，固定速率一致；真实长时高并发残留与性能指标待验证 |
审查记录：P级｜场景/时间点或tick｜实际证据｜影响玩家｜偏离规则｜建议改法｜复验；尚未实测记「待验证」，不可用单独效果美观替代同屏可读性。
