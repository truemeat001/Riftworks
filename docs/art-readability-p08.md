# P08 战场美术与可读性专项整改

设计基准保持已获用户认可的「手绘航海微缩剧场」（DESIGN.md、P05 角色/海图、新手/公开测试门禁），不另起风格、不改角色原画与逻辑判定。P07 实际 960×600 原生画面 `RiftworksP07-capture/screenshots/06-wave-combat.png` 显示一队橙蟹在同一路段部分遮挡、相邻 HP 条堆叠；另有三关密集单位同一行走相位的可读性问题。本轮提高辨识，不靠扩大地图/命中范围或移动真实敌人来掩盖问题。

## 1. 实际改动与原则

新 read-only RefCounted 表现模型 `src/BattleReadability.gd`：

1. **稳定、受限的敌人表现位置**。真实模型 grid.pos 对应世界坐标不变。按敌人 ID 固定 -1/0/+1 三个视效泳道，沿当前路径切向的法向做 5~12 逻辑像素微偏移（严格≤12px，且≤0.158格）；邻近拥挤时平滑增大，拐点前后0.24格内平滑混合相邻线段切向，避免角点侧偏瞬移。Boss 保持原始位置与原始大小。
2. **轻微视觉压缩与动画异步**。普通怪的表现缩放根据最近真实邻居连续缓动，最多缩小16%，不把前景怪缩小成不可辨识图标；不修改逻辑范围/伤害/路径，也不修改点击部署/预览位置，Boss 不缩小。行走clip按实际稳定 ID 加0/.125/.25/.375s相位；仍播放同一冻结素材，不伪称新增动作帧。后绘制依脚底 Y 排序，等 Y 用稳定 ID，避免后方阴影覆盖前景。
3. **每条血量与自己的实体关联**。读活体实际 e.hp/e.maxhp，优先 Boss 与实际剩余路径≤2格的敌，然后稳定 ID；默认正常28×4或Boss38×5条，局部密集时选择20/14px紧凑条和本地分行布局。所有条目分配真实 ID，用自己的脚底锚作为引导线起点；位置偏移时才画细线，不聚合不同实体的 HP。颜色从旧低对比填充/底槽调整为珊瑚暖橙 #F18B68 与墨灰蓝 #36515A，按 sRGB 相对亮度对比约3.48:1；细墨边和象牙顶线加强浅、深场景，Boss 用金顶线。轮廓和长度表达 HP，不靠色相单一识别。
4. **警告优先，仍可找本体**。用真实当前 path 最后点和活体剩余距离判定同 P07 核心告急位置，预留警示框，不将HP条布到其下；告急贴合阶段、位置与数量规则不变。若常规下方位置被警示占据，尝试紧邻脚点的有限旁侧/较高位置，通过连线保持实体归属。严格界内、相互分离、HP连线≤50px；超出局部容量则用精确该单位的小接触点圆弧，不隐藏警示或伪造混合血量，并公开 unresolved_count 作为 QA 失败指标。
5. **死亡与状态一致性**。缓存同一波最后真实绘制的偏移和缩放，死亡使用最后表现偏移/缩放，不从拥挤缩小跳回满尺寸。重开、切波、切关、tick回退清缓存；未实际绘制过该单位时使用安全默认偏移/缩放。命中、范围预览、真实 shots.to、P07 战后痕迹保留权威逻辑点；只有随单位移动的持续冰晶需匹配其表现脚锚，`BattleAtmosphere.draw_ground(..., visual_layout)` 已支持可选参数，不提供时仍兼容 P07。
6. **真实潮雾传递候选表现**。`BattleAtmosphere.draw_combat` 读取实际 `Run.tide_transfers`（若没有或为空则完全无新特效），每个事件从真实 donor 到实际 recipient，显示一条短时曲线水纹及方向箭头、目标小青环；无铜色伤害火花、不画额外杀伤圈、不触发声音、不改变模型。事件年龄来自权威 tick，仅<10tick时可见，离开 fight 自动停止。不同于原来的攻击 shot，不能被视为额外伤害/发奖。

Main 集成遵守：仅在绘制时读取 layout；脚底偏移、scale_mul、phase_offset、按Y绘制属于演出；地面接触线极轻且只在偏移明显时显示。旧重复 HP 条不再绘制，VFX/死亡之后绘制所有活体 HP，再绘制 CORE ALERT。没有移动 Run 敌人、塔、路径、射程、队列、点击目标、RNG 或规则结算。

## 2. 可复现验收

Godot 4.7.2 独立脚本：

    godot --headless --path . --script res://tests/readability_p08_tests.gd
    godot --headless --path . --script res://tests/atmosphere_tests.gd

**5892/5892** 项 P08 可读性断言及 **1627/1627** 项 P07 氛围回归实际通过；未将断言数汇报成玩家数量。

### 真实模型样本与几何诊断（不是新手体验/原生性能测试）

12 个真实 Run.start/step 波次（3关×2波×上下路线/额外裂隙或不同塔阶条件），测试两座合法末段塔+高阶拥挤，采样每5个权威 tick。实际抽样 938 次战斗快照、合计7,537个活体观测，最大同屏18名敌：

| 指标 | P07 几何对照 | P08候选 |
|---|---:|---:|
| 相邻 HP 容器相撞的成对观测次数 | 1,780 | **0** |
| 未能分配局部非重叠条的活体观测 | 未有布局约束 | **0** |
| 保守名义角色矩形重叠比例之和（统计所有快照/相交对） | 2584.89042 | 1960.61301（下降约24.15%） |
| 紧凑 HP 条真实观测 | 不适用 | 1 |

每个实际 sample 逐项断言逻辑位置、ID、足点/比例/偏移界限、危险语义、边界与警示预留、各血条关联唯一活体、HP条互不相交、局部连线长度、稳定 Y 排序。与调用前后完整权威状态快照及 RNG state 对比完全相同。重复同 tick 绘制得到完全一致布局。未测估计矩形与实际GPU遮挡完全一致。

额外使用明确标注的合成压力夹具：在入口、内点、核心、边界精确叠19单位（含Boss）或21普通单位，全部无 unresolved，检验极端容量而非宣称真实波数会完全重合；另验证路径拐点连续、死亡延续上一绘制锚/大小、复用ID新波清理、输入敌数组重排不改变输出、4种相位、死者不绘制。正常波规则仍由权威 Run 控制。

### 双尺寸实际图集诊断

可重现导出：

    godot --headless --path . --script res://tests/readability_p08_tests.gd -- --evidence
    python tests/readability_atlas_witness.py

产物 `docs/p08-readability-evidence/actual-run-dense-sample.json` 是上述真实样本中最大名义矩形重叠的记录（S3 W2，tick231，16敌）。实际冻结图集、实际敌身份、方向、源帧、角色渲染尺度和HP数据，在两种布局上用 Pillow LANCZOS合成并比较不透明像素被后绘制敌遮挡的比率。图为工程诊断，使用实际背景图、简化路线、无塔和完整HUD，**不是Godot运行截图**，不得上传成商店游戏截图。实际查看960版本，组内成串血条从相互压盖变为分行，角色分离有改善，Boss显著。

| 诊断尺寸 | 平均不透明像素被后续敌遮挡 | 超过一半被遮挡的敌 |
|---|---|---|
| 1280标称 | 23.81% → 15.94% | 4 → 2 |
| 960标称 | 24.18% → 15.90% | 4 → 2 |

此为单个有意挑选的密集实际状态，结合938次几何样本支持改进但不能外推所有视觉、帧率或玩家理解；剩余两名敌仍有较大遮挡，刻意将表现偏移/缩放限制得足够小，不为消除重叠伪造世界位置。实际GUI观察有无地形、塔、技能、血条/告警、HP线交叉、敌我遮挡、快速移动跳变仍必需。

## 3. 继承美术与尚需改进

- P05/P06/P07批准角色图集未替换，40个源姿态、136条目、3头像，P07已做明暗底与双尺寸三轮素材逐帧验证。P08 不称有更多独立绘制帧或新四方向姿势。图集 SHA256 5c002c705fafff06ddcc3f394762c6aae958383f5041a2735882f59ec8841e34，manifest a17c8a1ecfdabb010f845ad501962da02f6f12fcb19a0727c244675ac1e1998b。
- 本轮实际运行只加稳定相位/姿态显示偏移，不重新生成帧、不做黑金像素回退。升阶仍为饰片+数字，未制作独立成长形象。建议后续在真实试玩反馈表明确敌类辨认、告急识别、两倍速动作阅读、角色升级视觉期待。
- P08真实图形验收门禁：1280与960分别拍**实际游戏**无遮挡UI图；开启声音与关闭声音都能区分来向、灯塔告急、冻结/传递；观察一个最密集波次HP条对应实际单位、无重复或消失、同一脚位死亡无大小/位移跳跃；近危告警互不覆盖；实际合法部署和路径不受表现偏移影响。若同屏密集仍看不清，玩家测试后优先针对局部 silhouettes/分层做调整，不擅自改变移动/判定。
- 资产/几何/脚本通过不是实际 WebGL2 可玩、低端机 p95/p99 通过、真人可读性或好玩结论。需用最终冻结整包真实截图/录屏、实际硬件和玩家无说明任务验收。源图/离线诊断明确不作为真实商店截图。
