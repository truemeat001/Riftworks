# Riftworks 玩法设计与审查规范 v1.0
适用于新玩法、改版和独立审查。必须区分已确认规则、设计建议、实际代码、计算/模拟和玩家证据。视觉与音频遵循相关规范，但不代替机制验收。当前实例以 P05 冻结的 Run.gd 为准（SHA256 7f623075e85a6f4f8ce898c9622c75f0d605694be1a5c114b06570088bd2e0e0），新建议不改变已上传版本。

## 1. 输入、体验和核心循环
任务｜场景｜目标玩家与体验｜原规则版本及依赖｜要验证的假设。首先定义玩家反复做的动作、可见信息、挑战、反馈、结算和下一轮。MDA 从希望体验倒推可观察行为与机制：例如“随机挑战中的自主构筑”→玩家根据抽到的不同单位、遗物和下一波预报调整策略→统一随机池、有限经济、回收、合成和空间覆盖。不要以概率表、按钮数量或美术特效证明趣味。
**本项目一言循环**：读下一波预报，花局内金币随机招募或留钱，选择保留/出售/合成及布阵，抵御敌袭获得金币与经验判断，再用同一构筑适应下一波地形与敌人。
- 开局固定15生命24金币、三关各两波；纯随机单入口、无三选一、无真实金钱。
- 玩家自主开始，自动战斗；未通关波可损生命但下一波有结算，Boss漏出即败，生命耗尽即败；最后Boss击杀且该波结束存活才胜。失败/胜利重开局；跨关回仓但保留等级/遗物、钱与生命。P05没有局外永久养成承诺或联网。
- 体验目标（建议）：入门知道如何部署且能在前两波做有效决策；有经验者能从组合选择、不同行为风险、分路与增幅得到不同适用情境。不能靠指定强角色或某单一位置无条件支配。

## 2. 关键决策表（P05已确认规则）
| 决策 | 玩家当时可见 | 选项 | 代价 | 结果/何时有价值 |
|---|---|---|---|---|
| 探索/留钱 | 金币、动态概率、仓位、已知下波 | 6币抽一次 或 留待下波 | 6；留钱牺牲当下战力 | 缺覆盖时抽，已够应对可保留灵活性；无利息，不宣称留钱天然更优 |
| 出售或利用已有 | 角色/遗物、R等级、实际返还 | 保持、出售4/8/16或每遗物阶4，然后可再抽 | 基础抽售净损2币；失去现有战力及联动 | 不合构筑可回收，但多次追指定角色消耗未来选择 |
| 合成或分散 | 同职业同阶、当前覆盖和R等级 | 两同类同阶合R+1（最高R3）或都用 | 消耗一名角色、减少覆盖点；不另扣币 | 同路径/槽位紧张时优先升阶；分路/控制覆盖不足时保留两个 |
| 布置/移动/收回 | 实际活动及保留路径、格位、射程、角色属性与联动 | 覆盖路程、混合近邻或分散 | 格位和5部署上限，无额外币费 | 控制/输出联动对快群与重甲；第三关靠近增幅格有不同收益 |
| 闸口路线/第二关风险 | 真正两条路长度、敌数/HP、现有覆盖、额外奖励 | 第一关切长/短；第二关开/关附加高血敌路线 | 开无预付费，但更多敌与漏怪风险，零漏才+6 | 阵容强且两路覆盖时开；资源不足期关；不能当福利按钮 |
| 开战 | 预报、至少1名部署 | 开战或继续准备 | 开战后冻结抽取/交易/部署 | 无强制计时；根据预报安排，而非抢按钮 |

## 3. 可复现规则与边界表
| 触发 | 判定顺序 | 状态变化 | 结算 |
|---|---|---|---|
| 探索 | build→余额≥6→检查拥有、遗物未满→确定有效分类→抽类别和类别内等权项 | 扣6，单个角色ID或遗物+1，单条真实结果；少于2个角色强制角色，满类别排除 | 动画免费跳过，不推进RNG/多扣费；无池/余额不足拒绝，状态不变 |
| 部署/收回 | build、存在ID、格合法/未占用、上限5、不可落于全部保留敌路及增幅格 | 原ID从仓转场/移动或反向回仓 | 不新增/删除对象，不影响币、RNG；误触取消无变化 |
| 合成 | build、不同ID、同类同阶、R<3 | 保留第一个ID，消耗第二个；若第一在仓而第二在场，继承第二格，否则第一原格 | 不扣币，R+1；两个均在仓仍在仓 |
| 出售 | build、合法对象/阶位、明确确认绑定；最后一角色出售后无法凑6则拒绝 | 角色移除或遗物等级−1；合法返还 | 对象变更取消旧确认，拒绝无损 |
| Start | build且场上≥1；冻结预报 | fight，初始化 pending/冷却与波次计数 | 同一确认一次，战斗不能修改构筑 |
| 同Tick | 先生成→移动与终点判定/衰减slow→每塔按现有数组顺序对尚活的最短剩余路线者攻击→清除死敌→清理表现事件→判定失败/波结束 | 同tick先到终点的敌不会再被击杀；Boss漏立即终局；护航联动依当前slow及攻击排序 | 不以渲染帧、倍速、动画回调重复结算；同距当前按敌数组顺序，若要改必须记录 |
| 波次清空 | HP≤0优先失败；最终波还要求Boss击杀；其余清空即结算（即便普通漏怪） | 非最终+12，第二关开放且零漏额外+6；下一波/关回build，跨关回仓重置路线状态 | 最终不额外发普通波奖励；无源重复领取 |
| 重开/恢复 | 活跃局确认，取消无损；局终可直接 | reset(seed)/新seed重置局内状态 | 当前本地权威Run；不承诺崩溃存档/联网恢复 |

关联：钱→探索结果→直接影响部署、合成与遗物全局增幅→波次结算→下一波资源；地形促调整而不抹消既有构筑。增长和概率分析见 [数值规范](balance-design-standard.md)。

## 4. 最小原型和验收
本轮一次只验证一个可反证假设，冻结版本/seed、可见信息、目标指标和操作者类型，先用最少两种对照策略、同一输入预算，再观察真实玩家。不能把开发者通关或机器人胜率当玩家独立测试。
- P06首个建议假设：给新手看真实攻击范围覆盖与首次合成用途，无需改经济/伤害即可更懂布阵。最小原型只在P05现有站位、预报增加轻量可取消首次引导；同seed/同规则A（无引导）B（有引导），无说明玩家如何布阵/理解拒绝、首次部署时间、退出后的下一步；建议至少8名各组（待招募），记录首次两波、操作错误与主观原因，不把小样本当统计显著。
- 第二个独立假设（不要同时改第一项）：在第二关同阵容同预算，分路布局在特定压力下优于聚团而关闭风险仍有价值。固定种子与真实抽取，比较集中/分路、开关各两种策略，记录漏怪位置、剩余HP、额外奖励和最终胜负；当前距离覆盖仍易集中，不能以概念图声称已解决。
- 回归用例：开局四抽、余额/满池、合成上限、最后单位出售保护；同tick生成/到终点/击杀/状态到期；全部活动及非活动路径冲突、仓位满、跨关回仓；风险有漏无奖励、无漏+6；Boss逃即败、HP耗尽不能正常结算；重复开战/确认、暂停/倍速30/60/120下有序状态一致。

## 5. 审查与待确认
