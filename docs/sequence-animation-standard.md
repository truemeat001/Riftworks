# Riftworks 序列帧动画设计与验收规范 v1.0
适用：角色、敌人、图标、按钮、招募开箱、状态特效、转场。美术及交互遵循 [DESIGN.md](../DESIGN.md) 与 [交互规范](interaction-design.md)，工程接口以 [P05 角色图集](animation-p05.md) 为当前基线。非像素画不是放弃帧动画技术。

## 1. 每次输入（设计/制作/审查）
- 动画对象、用途、开始→峰值→结束动作描述；参考底图/风格/关键姿势各自职责。
- 实际显示尺寸、统一单帧源画布、目标总时长、固定FPS或显式逐帧毫秒、循环/单次、锚点坐标、方向、交付格式。
- 缺参数标「建议值」或「待确认」；先评审关键帧再补中间帧，不以生成随机帧替代动作设计。

## 2. 帧表及状态设计
每帧记录位置、轮廓、亮度、alpha、停留时间；全帧时长之和等于目标总时长，镜像不自动创建新方向语义。强调帧停留可延长，中间快速帧可短。循环必须检查尾→首三轮；一次性结束明确停末帧、隐藏或回静态。
### 示例：遗物图标扫光（建议，不是已实现）
实际48×48逻辑像素，源128×128 RGBA，锚点中心(64,64)，0.48s单次，保持同一张底图不动；扫光为单独裁切至轮廓的半透明光带。亮度仅表示视觉效果，不代表等级或概率。
| 帧号 | 停留 | 本帧变化 |
|---|---:|---|
| 001 | 80ms | 静止底图，光带alpha=0，预备 |
| 002 | 60ms | 左侧边缘进光，中心x=4，宽12，alpha=.20 |
| 003 | 50ms | x=28，宽16，alpha=.48 |
| 004 | 50ms | x=55，宽18，alpha=.72，达到峰值 |
| 005 | 50ms | x=82，宽18，alpha=.60 |
| 006 | 60ms | x=105，宽14，alpha=.35 |
| 007 | 60ms | x=128，宽10，alpha=.12 |
| 008 | 70ms | 退出轮廓，alpha=0，回静态 |
总和480ms；光带不改底图、不移动锚点、不循环；重复触发按表现策略排队或合并，不重复发奖。

## 3. 画布、对齐与生产
- 固定角色身份、镜头、比例、光向、画布。UI图标以中心/指定点锚定，站立角色用鞋底与地面接点，漂浮敌人用身体稳定轴；不能每帧以紧裁剪矩形中心代替锚点。
- 底图、变化层、阴影、血条、文字、星级、技能反馈分层。静物不变区域尽量直接复用，避免反复生成导致纹理/细节漂移。用洋葱皮叠看相邻帧，对齐不动部位、脚锚、尺度；跑步需可见换腿/换鳍，不能两帧只是平移。
- 先输出关键帧（初始、预备、峰值/命中、回位/结束），再补间。用参考角色固定造型，逐步修改单帧；不同角色、方向、动作分开生成。真正前/后/侧方向按需求制作，左右镜像仅在不破坏身份时允许。
- 输出源图保留原始 RGBA 与源文件；P05 角色使用400×400画布，脚/身体锚点(200,310)，8bit alpha；相邻帧使用同一比例，不缩放到相同紧包围盒。UI图标48px为案例不是统一的角色尺寸。
- P05手绘非像素运行时 LINEAR，2px四边和四角外扩防串色，紧裁 AABB 后记录 `rect:[x,y,w,h]`、`offset:[x,y]`、原画布、anchor、序列长度、fps/loop。偏移单位统一源画布像素；运行时将 offset 与尺寸按同一scale绘制。透明边缘检查的是alpha、色边及实际采样；面积节省不等同显存节省。
- 文件命名：`actor_pulse_attack_r_001.png`、`fx_relic_shine_001.png`；序列补零，Sprite Sheet附帧数/行列/顺序/每格尺寸/时长/loop；紧裁 atlas 附 JSON。源稿及原始提示、版本和SHA256留档。禁止孤立PNG无元数据或仅GIF作为游戏资产。

## 4. 表现与权威逻辑分离
固定20Hz逻辑Tick负责命中、伤害、取奖、售卖、死亡；动画只反映真实事件，不决定结果、不等动画结束结算。攻击起帧/峰值与事件有可追踪映射，快速攻击可缩短表现或合并但不丢事件；受击不反复卡第0帧；死亡优先，播毕回收、不能被idle/attack打断。暂停冻结模拟相关动画，倍速只改变表现节奏与tick推进；切关撤销旧演出。UI开箱已有免费跳过，跳过不得扣币/再发奖。

## 5. 验收记录与审稿格式
| 检查 | 验收 |
|---|---|
| 静态逐帧 | 裁切、源比例、锚点、重复或独立姿势、轮廓/透明alpha；深色、浅色背景分别合成；脚底/中心洋葱皮叠加无非预期跳动 |
| 实际尺寸 | 1280×800、960×600的游戏角色/图标真实大小，低于48px的图标检查缩小，观察手脚/武器动作和边缘，不用放大图代替 |
| 节奏 | 目标时长逐帧求和；目标速度连续播放，循环至少3轮，尾首衔接；单次结束明确归位/隐藏/停末帧 |
| 事件 | 真实攻击/命中/受击/死亡、开箱，暂停/倍速、频繁连续播放不重复伤害/取奖；同输入不同渲染帧率(30/60/120)状态一致 |
| 工程 | manifest与PNG/源哈希、AABB与offset、帧序、相邻采样外扩、无缺帧；可重新构建并载入，不把临时源稿导入运行包 |
设计输出：动作节奏+关键帧+完整帧表。制作输出：正式素材、帧表、尺寸、锚点、时长、播放方式、源稿与测试证据。审稿：时间点/帧号｜可观察问题｜建议修改｜复验方式，区分阻断、普通、可选建议；没有执行的测试必须写待验证，不从接触表或GIF推论真机表现。

## 6. P05 当前基线（已验证与待验证）
- 友方 idle 2帧@4fps=0.5s循环，attack 6帧@18fps≈0.333s单次（四独立源姿势、停顿与回位）；敌方 run 4帧@8fps=0.5s循环，hurt 2帧@12fps≈0.167s单次，death 4帧@9fps≈0.444s单次后隐藏。左右镜像有效；真正四方向和细分升阶造型待扩展。
- 已实际通过：136条目、40独立姿势、3头像，1284项图集与76项素材独立检查、像素重建/alpha/锚点/镜像/2px防串色；源图静态预览、实际原生截图1280与960，战斗事件与暂停/倍速操作已测，逻辑不变。
- 待验证/继续优化：每类型动画在真实展示尺寸逐帧记录、深浅底叠图的完整逐帧肉眼审阅、循环连续3轮的录屏证据、所有高攻速边界和死亡回收在实际GUI中的长时间观察；密集怪物重叠及UI次要文字不属于动画帧表逻辑缺陷，但影响可读性。
- 具体 P05 素材文件和测试见 `animation-p05.md` 与 `playtest-p05.md`。不得将上述帧数称为全部独立原创源帧或最终动画品质。
