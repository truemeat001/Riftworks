# Riftworks P04 — 《裂潮驿站》目标级美术方向

> 目标：先做一关可真实游玩的精致竖切，不把素材质量平均摊到所有关。Tidecross Ferry / 折潮渡口是验证战斗画面、人物辨识与抽取反馈的代表场景。P03 世界观仍成立；不沿用 NGame 画风、角色或旧战斗设计。

## 一、画面主张：让一个海上驿站真的活起来

**主视觉**：断裂的木桩渡口泊在浮陆浅滩，潮水退去显露盐渍石桥；潮汐行者在码头锚位持武器驻守，裂潮生灵沿着航道涌向航路信标。俯视棋盘用于清晰交互，画面从略带俯视的角色造型、材质和局部阴影制造纵深。不要给所有格子加醒目边框，也不要将背景做成大张未落地概念插图或塞满装饰的像素墙纸。

**目标质感**：手工高级像素艺术，清晰块面、统一光向、小调色板、短边高光、亚光材质。避免统一粗黑描边、密集随机噪点、塑料渐变、过量发光以及把大像素简单放大伪装细节。轮廓和关键道具优先于纹理；局部斑驳、铜氧化色和海盐才表达使用痕迹。P04 是工程与目标质感第一次对齐，不把尚未实机评审的贴图称为发行级成品。

| 功能层 | 视觉设计 |
|---|---|
| 世界背景 | 深蓝灰海面、礁石边缘、青灰苔藓、赭金木栈道、潮泡与靠岸船桩；色彩低饱和，形状有明显大小变化 |
| 路线 | 相同材质的连贯通道，盐渍较浅、方向暗纹，活动路线强调边缘/箭头；无敌时一眼读懂起点、终点和弯折 |
| 可部署区域 | 不默认满屏强烈格线，鼠标到格位时清晰高亮，已占格与非法格在轮廓/图标上区别，保持 P03 逻辑格位准确 |
| 敌人与友方 | 高于背景的明度与干净边缘；友方冷青、米白、铜金，敌方暖珊瑚、墨紫和骨白；不只用颜色区别 |
| 战斗反馈 | 目标明确、准备→释放→命中→消散；局部高亮、弹道与脚底特效在人物前后分层，血条和路径不得被遮住 |

配色锚点：海深 `#182c38`，浅海 `#314952`，雾蓝 `#52717a`，码头暖灰木 `#91735a`，铜高光 `#c59a55`，友方薄荷 `#8ed9d3`，敌方珊瑚 `#dc735f`。这些是方向色而非强制逐像素色码。主光左上，阴影右下，武器金属的少量高光比背景最亮点更亮。

## 二、角色要成为第一视觉焦点

建议在 **1280×800 逻辑视口，常规角色可见高度 70–88 px**，体型较小的快速敌略低，Boss 105–125 px。相对 P03 的 54px 格位，不是无限放大精细素材；优先把棋盘与 HUD 的画面占比改合理，角色可以向上超出格子但脚底锚仍在格中心。场上站位线、选择圈和攻击范围不得被角色贴图掩盖。960×600 必须不发生按钮裁剪、格位漂移或相邻角色永久遮挡；如果缩放令细节混叠，优先优化布局和源像素比例。

| 角色 ID | 视觉定位 | 必须存在的形状线索 |
|---|---|---|
| pulse | 铜鸣游击手 / Copper Scout | 修长风镜脸、软帆布斗篷、横向长铜鸣枪和冒一点青烟的装置；预备举枪→脉冲射击 |
| frost | 潮雾织师 / Mist Weaver | 低重心宽帽、潮壶与潮雾丝带；施法抛出冷色雾流，而非蓝色泛光球 |
| burst | 礁锤护航员 / Reef Guard | 宽肩工装、盾与短重锤；蓄力时锤弧可读，落点与面积伤害标识一致 |
| crab | 裂潮寄居蟹 / Rift Hermit | 巨螺壳、短足、钳，爬行交替步态 |
| sail | 风帆兽 / Sailbeast | 前倾瘦长重心、三角帆背、疾跑腿部交替 |
| urchin | 棘潮盾兽 / Shellguard | 甲壳保护前胸、棘刺肩背、沉重步态；不要像第二种快怪 |
| boss | 潮渊领主 / Abyss Warden | 倒锚双臂、发光鳍冠，重心厚重，脸部有明确眼睛；保留身体全貌和脚底锚点 |

复用 P03 的稳定脚锚、紧 AABB、1px 采样保护、Nearest、逐帧 rect/offset 清单；新像素帧要求真实肢体交替和姿态变化。普通塔和敌都必须为角色，不以独立发光几何代替。攻击事件触发视觉演出，不从动画结束反推逻辑伤害；死亡只结束画面表现，不能影响权威结算。P03 的动画状态文件和命名继续兼容，能在素材质量替换时不重写战斗规则。

## 三、船上补给箱（核心交互，不是独立剧情）

把随机抽取动机接进场景：码头驿站有一只铜木补给匣，通过未知招募信号带回一位行者，遗物抽取则打捞回匣。箱体本身要有轮廓（箱盖、锁扣、锈铜边、木纹与青色潮缝），放在可见的准备区或紧邻招募按钮，与实战路线不冲突。

借鉴 Fortnite 的**原理**：物体开合、奖励突然弹出、较重的停顿，以及奖励落向明确归属；不复制视觉资源、箱形、音效、UI、商标、具体稀有度设计或商业化玩法。P04 各抽取当前等概率，设计不表现不存在的稀有度、诱导性假近失或现金购买。

### 动效分镜（建议总长 ≤0.9s）

| 相对时刻 | 表现 | 功能约束 |
|---|---|---|
| 0–0.08s | 点击 Recruit/Recover relic，金币立即减 6，出现一枚航币入匣尾迹 | 仅当底层抽取成功；不足/满仓不扣币、不亮箱、不推进 RNG |
| 0.08–0.24s | 箱体小颤、锁扣开、箱盖弹开；缝光聚集 | 不全屏覆盖，开始波次等其他操作可按原逻辑继续，表现层不能成为额外的经济状态 |
| 0.24–0.42s | 一次清晰青金色短光脉冲，**真实已经抽中的**角色完整剪影或遗物 icon 上弹并稍过冲，应有可辨认物体而不是连续文字轮播 | 出结果名称、职责/效果和新余额；抽中普通对象也有完成反馈，不伪造稀有等级 |
| 0.42–0.82s | 物体缓落；轨迹指向预备队格或遗物列表，目标位置短亮；结果可选中查看、部署、释放/出售 | 优先操作可用；连续点击可合并/结束上一条视觉轨迹，新结果不能覆盖未显示的实际资产或触发额外抽卡 |

辅助声音建议（后续有资源才接）：开箱木扣 + 铜锁短促声、上弹轻气流、归仓清脆轻音；允许静音。不要引入持续炫目的闪烁或单次大面积白闪。支持低动效时直接显示结果，允许玩家继续。结果文字/头像停留到下一次准备操作或下一次抽取，既可快速连抽又可复查。开箱与金币/奖励的权威状态绝不依赖播放完毕。

## 四、UI 与字体：视觉服从操作

方向是更大的沉浸式战场，而不是 P03 的三栏技术调试板。上方短状态主轴（稳定度、航币、波次与阶段），预备队紧凑连贯，遗物与选中角色详情采用上下文检查面板，避免所有说明常驻占去战场。具体控件位置可根据实机空间调整，但操作序必须保持：招募/打捞 → 可见结果 → 选中 → 放置/训练/释放 → 开战。每个操作都看得见当前成本或收益、选中状态与阻断原因。

- 使用来源许可清楚、实际小号字可读的字体；若尚未具备合适像素字体，继续可靠的系统/项目字体。标题可以有像素化装饰，正文数字和操作标签优先清晰；不能为了画风强行低分辨率字号或模糊缩放。
- 同一视口内图标、数字、按钮的边缘和间距统一；普通按钮用有质感但轻量的框，不应用每个按钮不同的装饰。选中态、不可用态、键盘焦点不只靠颜色。
- 不应仅依赖英文长文字解释状态；角色卡显示定位、星级，仓位显示稳定图标/缩略图；对当前英文实现可先采用短动词 Recruit / Relic / Deploy / Train / Release。
- 战斗中角色和命中反馈最大优先级，抽取动画仅准备期触发。关卡过渡、胜负、暂停、倍速与重试操作仍可完成。

## 五、验收与风险门槛

本轮先冻结一张 Tidecross Ferry 画面方向和一套角色资源，然后运行 P04 真实画面，不要只在 PDF、概念图或原始 spritesheet 中自我评价。

1. 截图至少包含准备期满队或多角色、抽取弹出中、交战中和执行结算；在 1280×800 与 960×600 分辨率确认。检查战场占比、角色清晰度、敌路、金币和所有按钮的实际可读性。
2. 在普通角色攻击、怪物沿路移动、Boss 近距离三类情况下看实际录屏/连续截图；角色脚不漂移，腿真实交替，攻击动作与逻辑攻击事件一致。若只有 atlas 自动测试，应标记未完成真实动作验收。
3. 连续抽取五次，逐笔核对一次成功扣 6、同一真实结果显示一次且入仓；拒绝抽取无箱动画/扣款，售卖仅结算现有对象；低余额、满仓、快速点击、暂停/倍速、重试与跨关不会遗留箱结果。
4. 仅角色立绘、静帧和背景都有实际原创来源/版权记录；不使用旧角色/旧场景的美术资产，也不使用 Fortnite 素材。
5. 过关画面有足够品质并通过真实操作后，再扩展后续关的背景主题；如果本轮仍只是占位或 native GUI 不可用，必须在交付说明中如实标注，不把“精致方向”误称为“最终发行级美术”。
