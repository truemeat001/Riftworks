# P10-lab 蟹怪行走体验量化评审

## 1. 可复现事实：玩家反馈有明确的技术证据

P08/P09 的图集和 manifest 完全相同，分别 SHA256 `5c002c705fafff06ddcc3f394762c6aae958383f5041a2735882f59ec8841e34` 与 `a17c8a1ecfdabb010f845ad501962da02f6f12fcb19a0727c244675ac1e1998b`。本评审不修改 P09。四帧都是项目真实资产，不是重画。
- 图集裁切矩形宽 153,160,153,153，偏移 x=-88,-40,-97,-42；y=-110,-110,-109,-113。
- 源画布400×400，脚锚 (200,310)，8fps×4帧＝0.5s；`Main.draw_character` 将偏移和尺寸同时乘 scale。角色以 idle 尺寸限制宽55、高53，实际 scale=55/153=.359477；960×600 为 .269608；拥挤乘 .84–1。
- 原生成脚本 `detected_anchor()` 对没有手工 anchor 的 crab，以 alpha≥128 的最低10%轮廓 bbox 中点为 x。四帧原片测得 anchor x 121、54.5、133、58。不同步态中最低接触腿变化时，这个算法实际改变身体横向注册点，而不是固定身体坐标。四帧底部 y（alpha≥128）都为 -1，故仅靠“脚底 y 对齐”检查无法发现问题。
- `Run` 真实移动 20Hz（50ms），速度为(.95+.12×stage+.12×index%3)格/秒，tile76，普通速度 .95–1.43；减速因子 .55 至 .2。Main 动画按全局 tick×.05＋ID相位偏移固定8fps，并非按实际路程；因此慢速状态更明显地出现步态与移动不一致。20Hz 使8fps帧实际停留交替100/150ms，并不是稳定125ms在显示层连续插值。现有逻辑不需要改变；未来可用表现层本地路程相位做距离同步。

逐帧可见：第1/3帧壳体位于锚点左侧，第2/4帧明显在右侧；底部支撑剪影由较宽变为窄，壳/触角/足被生成成不同独立姿势。不能把下缘重叠变化等同于同一只脚是否打滑，因为没有可验证的腿ID/关键点。接触表仅静态观察，不声称肉眼看过动画。

### 真实规则回放

隔离临时项目中运行原始 P09 Run.gd + BattleReadability.gd，seed437，实际付费抽取一个角色、合法部署(11,7)，实际 start/step 80 ticks；无改战斗代码。捕获360条实际 normal enemy trace（世界位置、render anchor、dir、scale_mul、state、frame index）。350个连续同向水平 run interval，以实际 anchor 位移叠加对应帧壳体中心得到：

- 原版：72/350 逆向（20.57%），位移 -16.01~+22.74px，最大偏离 anchor 位移 19.62px。
- 候选：0/350 逆向，位移 +3.40~+4.64px，最大偏差 .282px（含拥挤缩放）。

这是实际引擎规则与实际图集的数据证据；GIF是以捕获状态和相同缩放/锚重建的离线播放，不是实机 Godot GPU 截图。环境无 DISPLAY/Xvfb；浏览器实机和人类观看质量仍待验收。

## 3. 最小隔离候选

原图集不动，run四帧相对当前x修正 [0,-44,+10,-43] 源px（左向镜像取反）。上半身 alpha 中心固定在首帧基准附近。候选 manifest 是实验文件，不应直接当生产 manifest（生成器元数据尚未更新）。若采用，先改 generator 的 crab anchor 策略，并用原图源重建镜像、atlas metadata，独立回归 AABB/offset/padding；hurt/death 切换也需单独检查。现候选只处理 run 横向注册，不能宣称脚部行走已自然。

## 4. 生产级后续方案：稳定身体 + 真实交替支撑

不更改怪物模型/速度/战斗规则。用原 crab 的稳定色块、眼睛、甲壳纹理、朝向作为确定的身份参考；不再独立随机生成每帧，先锁定壳体层（固定中心/尺寸/光照），再设计分层的支撑腿 A/B、近侧钳、眼神和少量 y 起伏。建议8独立动作帧，每周期走36px（常速 .95tile/s、0.5秒参考），源单位≈100px；每步相位进度约12.5源px，支撑足局部后移抵消实际 root motion。动作帧表：

|帧|支撑组A|支撑组B|壳体|
|---|---|---|---|
|0|触地前端|离地回收|基准|
|1|触地向后|抬起摆动|轻微下压|
|2|触地中部|前摆|低位|
|3|触地后端|接近触地|回基准|
|4|开始抬脚|触地前端|换重心|
|5|抬起摆动|触地向后|轻压|
|6|前摆|触地中部|低位|
|7|接近触地|触地后端|返回F0|

这是动作方案，不是假装现有人工帧已具有这些脚部对应。每帧以统一400×400固定体轴/脚平面、单独标注真正接触点，8帧 loop 不靠补复制重复帧。播放相位按实际 model distance delta 累加，减速同步；暂停/零位移停止相位，倍速只影响模拟实际速度；相位仍然是 presentation-only。现有四向镜像只有左右语义，竖直段采取最后有效朝向避免瞬间翻转，若需真实前后方向另做一套关键帧。禁止动画相位反馈伤害、速度、碰撞或路径规则。

建议下一轮量化准入：1280/960真正展示尺寸、至少3轮；相邻F末首单独审查；上部稳定体轴水平漂移≤1逻辑px、y峰峰≤2px（除设计明确身体起伏）、真实直行非转弯 body forward 不反向；对人工标记的*同一支撑足*在支撑阶段，实际路程扣除后世界漂移≤1.5px/tick（先做基准校准再锁门槛）；每组交替触地且无异常缩放、轮廓/纹理跳动；必须有人观看实际播放、实机正常/slow/x2/暂停、30/60/120fps和转弯，而非只看图集统计。密集场景另测遮挡和角色可分辨性。

## 5. 文件与重现方式

- `audit_crab.py`：从P09精确提取原/候选各4张固定画布并测量，两个显示尺寸接触图、三轮简单直线GIF。
- `crab-metrics.json` 全部指标及源哈希；`trace_crab.gd` 实际游戏规则获取状态（在隔离项目复制 P09 src/Run.gd, BattleReadability.gd 与 project.godot，headless 执行）。
- `crab-real-run-trace.json` 360条原始记录，`review_real_trace.py` 复算摘要和使用原关卡背景离线回放，`crab-real-run-summary.json`。
- `candidate-manifest.json` 仅实验偏移数据，不能直接覆盖P09。
