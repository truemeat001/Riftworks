# P10 独立审查：战斗特效、弹道与战场氛围公开试玩门槛

## 制作人结论

**暂不达到公开测试标准。** P09 的事件真实性、生命周期和层级基础较好；P10 新双灯塔仍是独立规则候选，旧 P09 表现直接套用会导致严重的危急方向错误及警报出屏。用户新增要求：攻击特效和弹道明显、有辨识度，因此新增三个职业的表现合同，而不是单纯提高亮度/粒子并发。

本轮未修改 P09 或正式 P10 生产代码。审查依据：`RiftworksP09/docs/vfx-design-standard.md`、`battlefield-atmosphere-standard.md`，角色动画独立 QA 另行负责。以实际冻版 Godot 4.7.2 脚本/资源和 P10 八波模型候选为输入。证据分为：
- 独立新执行 Godot 权威模拟：P09 vs 直接套用 P09 表现到 P10 模型（反事实检查，不声称已存在合入后的游戏）。
- 独立新执行真实 Main 场景/UI 回调，固定 delta 计时（无 GPU，非玩家真机录像）。
- 审视已有 P09 原生真实截图（seed437 六波胜利），原图 1280×800、独立缩放观察 960×600；评价截图中可见形状，不冒充完整动态播放或真人感受。
- 源码与几何推导；所有建议新阈值以「建议」标注。未做真实 WebGL/浏览器听音、真机 GPU 帧时或不同真人的盲测。

## 2. 阻断问题与改法

### P0 — Twin Beacons 双路威胁和警报语义失真（P10 合入阻断）
复现：合法 seed438 真正进入 stage2，wave0 tick1201；实际存活敌距南路终点 (11,7) ≤2格，旧表现却取 (11,0)。12 波双灯塔全部可复现入口缺失，1071告急tick矩形不在屏幕。
- 源：`BattleAtmosphere.gd:38–61` 仅 stage1/opened 判断第二路，draw_alert 主路末端；`BattleReadability.gd:137–147` 一项 warning_rect；`Main.gd` 入口、灯塔、AMP、背景 stage 分支硬编码 P09 三关。
- 几何：北出口 (11,0) 实际中心 (926,98)，旧 rect = (806,-34,154,26)，顶端和底端均出 1280×800，导致警报文字完全不可见；南路告急仍错误标北路。
- 对玩家：看不见真实危险，无法理解哪路漏怪、应把资源安排在哪个出口，违反规范的真正方向、位置、范围。旧阶段2晶石装饰还可能让新关卡看起来具有实际不存在的增幅。
- 修复：统一读取模型 active_lanes 或等价接口及各敌 route[-1]；两个真实入口/出口、独立路径提示、每出口告急数/位置/真实漏怪事件，按实际事件发声；两个警报都在可视 board 内，不与 HUD/血条/Guard 状态重叠。出口位置必须独立于当前选长路；两端共享真实 HP，不虚构两份生命。stage 识别使用关卡配置，不复制旧编号判断。
- Gate：两个方向、仅南、仅北、双端同时、无危险/击杀/真漏怪，真实 12 波重放；双路显示2/2，警报0错路0出屏0漏报0假报；静音也看得懂；现有 stage0、stage1 开闭、旧 Echo 新stage3、同屏峰值和旧原生6波行为回归。

### P1 — 用户已指出攻击表现弱，职业弹道不够显著（本次改进必验）
复现：现有真实 P09 Guard 战斗截图（尤其查看 960×600）攻击细直线可辨但极短且静态，不表现飞行头部。源 "BattleAtmosphere.draw_combat" 普通线宽 1.1–2.4逻辑px（960 页面仅约0.825–1.8px），u阈值控制4tick/3tick；通常1×200/150ms，2×100/75ms。标准规定短方向弧/实际命中，用户进一步明确要「攻击特效、弹道更明显」。当前不应把短线存在当飞行表现已做好。
- 以 **真实权威 tick** 扫描，动作起手/发射时刻必须有唯一 action ID、source ID 和实际 hit event（primary/secondary区分）；命中即时显示真实判定，不故意延后HP、死亡、slow，亦不虚构可躲避前摇。可做真实事件之后移动亮点/收尾 tracer，局部击点必须在确认 tick 显示；如果未来真的设计前摇/飞行伤害，先另行改变并验收玩法模型。
- 用 source weapon/render anchor / confirmed target effect anchor 的可解释位置：模型当前从格心画，目标视觉 anchor 为模型格心＋拥挤偏移＋13px；实测存活 Guard 同tick 命中点到可见脚锚最大25px。应保留历史逻辑坐标用于可追溯性，另存事件时的 presentation anchor，不追着后续移动的对象重放旧命中。守护拦截命中于实际接收者、关系线为曲折虚线，不在原目标生成伤害闪光或虚假第二命中。避免在原始格中心强行创造命中体积。
- 统一材质、窄幅峰值，形状而非只靠颜色；控制高频噪声，优先压装饰。弹道加强不可让HP/核心告急/实际目标更难辨。

**新增三个职业验收合同（建议初始尺寸/可见时间，等实际A/B确定）**

| 角色 | 起手或发射 | 飞行轨迹辨识 | 真实命中及持续态 |
|---|---|---|---|
| Brass Skirmisher 铜鸣 | 武器端1个方向清楚的短闪、姿态与事件tick对应 | 暖铜色实心头＋米白细高光、3–4逻辑px主线、逐段收束头尾；普通直向；导电为明显折线/短弧，真实额外链目标逐个标记 | 实际受击点1个脆窄环，正常命中小且短；导电真目标有独特折线及小闪，不多画范围 |
| Mist Weaver 潮雾 | 法杖端短霜纹，明显青白但不能遮脸 | 双层弧状雾核/凝晶头，3–4px主线；不将一条直线换颜色当机制区别 | 目标实际减速施加时的霜环＋四枚晶形持续，随对象移动，截止真实 slow≤0 或死亡；Boss减速不同仍真实 |
| Reef Hammer 礁锤 | 锤举→下击姿态，清晰重量方向；与真实事件tick对应 | 琥珀粗短蓄势/冲击，3–5px头迹，和长射线有形状/节奏区别；瞬时打击不伪装成飞行子弹 | 实际主目标放射短碎石；只在实际溅射者显次击，真实碎冰/Slow transfer采用破冰碎片连线。无真实范围就不画范围；若画边界必须严格按实际半径与坐标 |

可量化判定（**建议 P10 合同期**，不是现版已通过）：
1. 每个职业单独10次实际攻击，同 tick 追踪 from/to/source/target/tick/primary/changed HP，1×、2×、30/60/120 渲染及一次长帧；动画可视窗口至少建议 1× 180ms、2× 100ms（如果需要最短实时时间下限须明确并保持不影响逻辑）。关键形状在实际960页面至少连续3帧@30fps，路径主线建议可见≥2px实际屏幕，低亮的辅助尾可更细。真实无攻击时0假头/假击点。同一事件不得因绘制/恢复而重复。
2. 受击位置：事件时的可见角色锚与其 hit hotspot 在同tick 对齐，离对应角色轮廓合理内侧/边缘，偏离>5显示px应有依据（地面范围等）；不得错附相邻敌人。历史收尾可以驻留但不得被误读成新攻击。慢速、不同体型、拥挤横向错位、贴近射击左右方向及转弯均需逐帧验证。
3. 区分普通直向、Mist慢速、Hammer范围、Conductive折线、Shatter破冰、Guard拦截至少 6 类；无色图和静音下独立盲对照至少两遍（正常速度、2×）；独立QA在不读 tooltip 时指出发射角色、实际受击对象、是否slow、是否范围/拦截，以达到每类 9/10 次正确作为建议目标；真实玩家反馈另记，不把AI评分当用户群体指标。
4. Guard 用真实拦截事件对比同场 Hammer bypass；射线实际 recipient、盾牌闪和方向关系可读，原 intended 0假hit/0假HP变化，冷却盾牌以真实剩余 tick 表示；其他 chain/溅射命中不重复整个施法。
5. 密集最大覆盖：P09 真 trace 峰值16存活敌/15 impact/2 Guard；至少复验该密度及5塔、最高攻速/链/碎冰、双路同时、Boss告急、2×。事件相关核心受击和危险轮廓可见；建议最醒目瞬时装饰遮挡不超过战场面积15%、单帧高亮区域不超过8%（需定义alpha≥0.35遮挡mask/新增亮度mask，与背景A/B同帧计算，报告p95和最大），**关键UI/血条/告急文字0掩盖**。装饰溢出先减残余碎片/尾巴，不删命中与真实状态。不可用该建议面积阈值代替实际观察；先实测A/B再门槛确认。
6. 全局危险需1px以上的对比边缘，关键形状实际背景 contrast≥3:1（原规范）。纸底红字源色对比6.54:1；现有0.72 alpha红环在三处样本背景推导约1.98/2.59/3.34，提示真实边缘可能不足；采样不是实际告急截图，不声称已经证明实际 ring 失败。改深色描边/纸底轮廓后在真实多地图帧测。

### P1 — 最后一只敌还未播死姿就清除整个演出
实测 P09 37 次实际波末击杀与 phase transition 同tick，P10反事实35次。Main.gd:810–819 一边追加 deaths 一边在退出fight时 clear。对最后击杀（含最终Boss）玩家收束和死亡反馈可能变成凭空消失，尤其用户要求公开试玩手感。
修法：phase 权威立即结算，不阻塞按钮/奖励；以短收束层专门播放已确认最后死亡或 Boss 局部残影，限制≤0.3–0.45s并在新波/换关/重开时清除。对换关当帧需要保留旧关画面就用单独终局/转场反馈，不能把旧尸体画到新图。Gate：最后 normal/guard/Boss击杀、漏怪失败、快速下一波/重开，无 phantom kill、无旧图尸体、结算不等动画。

### P1 — 速度和 Retry 确认弹窗的瞬态时间不一致
新执行真实 Main 场景 callback（关闭自动process，固定delta重放合法seed437两塔首波）：第一个敌死亡 tick15。Pause后0.20s tick/age均保持；打开实际 Retry 确认后0.20s tick仍15但死亡FX age0→0.2，继续0.25s尸体消失且模型仍15。普通死亡在1×9逻辑tick（0.45s），2×18逻辑tick（0.45s），其他基于tick的攻击/Guard效果按2×缩短。此为精确原生业务代码运行证据，非真人录屏。重开后 tick0、death/trace/impact=0。
改法：同一模拟相关时序源（或显式定义可读真实时间下限并在paused/modal冻结），暂停/Retry确认都不推进逻辑相关特效。UI提示、静态环境层可明确例外。Gate：真实攻击/死亡/slow/Guard瞬态在Pause、Retry确认、Esc取消、确认重开、2×换速切换逐事件记录，状态与模型一致，零意外重播。

### P1 / P2 — 密集可读性与关联
P09 50491单位bars普通摆放成功；P10候选64129中8次fallback，需要修多警报矩形与密集布局后重测。Guard 赞成优先避开血条。P09 9230/9230 badge存在无隐藏，但9145次距离自身脚锚>25逻辑px（正常设计候选 Vector2(22,-19)本就29px，因此不是直接失败），拥挤时可能难判断哪个对象持盾；现有960缩放截图能看见盾但尺寸小。建议盾牌与归属建立短且低噪关联、紧凑最低尺寸和实际轮廓避让；不引入假护卫关系。独立QA测试遮挡组中实际护卫身份与真实准备/冷却，不能靠全局计数推断关联清楚。
- 现有 Guard 盾牌、关系线没有给 intended 假伤害（规则正确）。Guard flash 固定历史事件位置，若随角色移动误导才调整。对已死亡Guard不得显示 ready 状态。
- P09 告急 threshold 基于真实剩余2格、无假闪，但真实画面缺有告急的 native 录像。两种尺寸和实际警报+Boss/普通密集同时需录制。

## 4. 近期行动与验收结论

1. P10 场景/玩法集成方首先修两真实端点、active lanes、警报与画面层级；全输入、事件日志与 UI contract 按 P0 Gate 回归。若未达到不上传公开。
2. 攻击 VFX 实现方依新合同在三个职业先做实际渲染：每个角色正常/慢速/范围和明确飞行头/尾、Guard实际命中，留下正常速度实际录屏和对照帧；独立审核确认信息而非仅视觉鲜艳。合并死亡收束、时间冻结修正。
