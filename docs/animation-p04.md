# P04 美术升级与帧动画资产冻结

《裂潮驿站》P04 原创航海像素幻想；参考上一轮角色职责、世界设定及 NGame 的工程技术模式，**不复用 NGame 或 P03 任何角色原始图像**。本轮采用内置 ImageGen 重新创作 7 个角色和实际动作关键帧、折潮渡口代表性战斗地图、补给宝箱闭合/打开图。输出是真实运行时资产，不是只留在概念图中的设想；实际游戏中效果仍由独立 GUI 试玩验证。美术品质相较 P03 占位图提高明显，但此处不承诺全游戏发布级美术完成。

- docs/art-sources/：保存本轮完整 ImageGen 图、原始变体和最终清洁版本，仅用于工程追溯与再打包，不是运行时贴图。

| 角色 ID | 动作源关键帧 | 实际运行时动作序列 |
|---|---|---|
| pulse / frost / burst | 每角色独立 4 个 ImageGen 全身动作：站立、预备、发力、回位 | idle 2 帧（4 FPS，源 idle 与回位），attack 6 帧（18 FPS，4 个独立源姿势，明确停顿/回位） |
| crab / sail / urchin / boss | 每角色 4 个完整移动姿势 + 3 个受击/倒下源姿势 | idle 1 静态参考；run 4（8 FPS 循环，全为独立的移动关键姿势），hurt 2（12 FPS，受击+原站姿），death 4（9 FPS，受击、倒下、倒下停顿、躺倒） |

40 个不同源姿势，原始源图无固定等间距切片；最终运行时共有 136 个图集条目（含左右镜像和明确停顿重复）。不为未实现行为制造假动画：本轮没有给固定驻位友方额外制作移动/受击/阵亡完整动作组，也没有为纯沿路径移动怪物虚构攻击行为。上述素材不是手工逐像素逐帧修订的最终发行 sprites，独立源姿势间仍可出现 AI 生成的服饰细节和腿部运动幅度差异；检查实际动画节奏和锚点稳定性后再决定进一步细修。

## 真实生产方法

1. 内置 ImageGen 根据 P04 世界设定生成 7 角色原创全身概念，生成 3×4 友方攻击姿势表，4×4 敌人移动姿势表以及 4×3 敌方受击/倒下姿势表。为确保透明质量，分别再次调用 ImageGen 对敌人脚下误生的浅色地面线、补给宝箱外部灰雾进行清洁编辑，保留原始版本。
2. 对原图进行确定性技术处理：按高不透明度像素的投影空隙测量切片单元格，取 alpha>=128 的主体边界并外留 2px，**裁剪内部仍保留生成器提供的 alpha**。不采取抠掉四周所有半透明像素的方法。每个角色在一个源表中统一缩放，不按帧单独拉伸。使用 NEAREST 处理游戏像素尺度；逻辑主画布为 192×192，锚点 (96,148)，图集裁剪再恢复相应 offset。工作角色标称高度 92px 友方、84/86px 普通敌、120px Boss；运行时缩放按当前场景格子高度适配。
3. 身体姿态使用生成图本身，不使用 GPU 旋转整个人体假装朝向。按独立镜像帧表示左右方向（以相同垂直锚线为轴）；上下方向本轮使用侧面近似，真实攻击向量和轨迹由游戏表现层处理。左右脚动画由源姿势不同的腿部动作形成，而不是移动同一静态剪影。
4. 继承 NGame 实际技术资产思想：按接触区锚点、逐帧透明 AABB、1px 边缘和角像素外扩、缓存共用图集、最近邻纹理采样、固定逻辑 tick 和表现分离；对于 AI 输入图的锚点，采用主体不透明下侧 10% 区域中点估计，后续需要针对极端动作手动标注校准。图片的 alpha 与动画帧进度不影响逻辑攻击或随机抽取。

## 生成与验证命令

依赖 Python 3、Pillow（只在资产生产和测试阶段使用；游戏运行时不依赖 Python）。在 P04 项目目录运行：

    python assets/characters/generate_character_atlas.py
    python assets/characters/verify_character_atlas.py

本轮验证实测：136 帧逐一完全比对重建源 master 像素、alpha 裁切、offset、镜像、独立 1px 外扩、图集区块不相交、动画 distinctness。箱子两态完全比对从源图裁切与固定缩放后像素。图集占 1,222,656 像素，原画布同帧数直接平铺为 5,013,504 像素，节省约 75.6% 面积（不是显存或加载耗时实测）。对透明背景采用新清洁版本，实际图集预览中原来可见的敌人脚底白色向导线已去除，宝箱暗背景下的矩形灰雾已去除。
